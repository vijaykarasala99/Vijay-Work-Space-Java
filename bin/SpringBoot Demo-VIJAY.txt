📌 What Is Framework?
A: A framework is a ready-made or semi-developed software structure that provides common functionalities required for developing multiple projects.
✔ A framework provides common logic required for several project developments.  
✔ A framework provides reusable components (Classes and Interfaces).  
✔ A framework improves productivity by reducing development time and boilerplate code.

📌 Why Do We Need a Framework?
✔ To reduce development time and effort.  
✔ To avoid writing repetitive/boilerplate code.  
✔ To provide reusable components and predefined logic.  
✔ To improve code maintainability and scalability.  
✔ To increase developer productivity.  
✔ To follow standard architecture and best practices.

✔ Spring ORM (Object Relational Mapping)

>> Developers can directly work with Java objects. Since Java is an Object-Oriented Programming (OOP) language, Spring ORM came into the picture to simplify database operations.

✔ Spring Security (Authentication & Authorization)

>> Spring Security is used to secure applications.

>> Without security, anyone can access application details, APIs, or sensitive information.

>> In Spring Security, we learn Authentication and Authorization.

>> Authentication = Who are you? (Login / Identity Verification)

>> Authorization = What are you allowed to do? (Access Permissions)

>> Suppose we open a BookMyShow-like application:

Role ADMIN:
✔ View theater revenue  
✔ Add new movies  
✔ Change ticket prices  

Role USER (Moviegoer):
✔ Browse movie timings  
✔ Select seats  
✔ Book tickets  
❌ Cannot view total application revenue  

>> Spring Security helps us secure applications by controlling login, access, and permissions based on roles.

✔ Spring Cloud

>> Spring Cloud provides features like API Gateway and Fault Tolerance.

>> API Gateway acts as a single entry point for all client requests and routes them to the respective services.

>> Fault Tolerance (Spring Cloud Circuit Breaker / Resilience4j): If the Flight Service is down, the application will not crash.

>> Users can still access Hotel Booking and other available services, while a message is returned like: "Flight service is temporarily unavailable. Please try again later."

✔ Spring Batch (Bulk Operations) 

>> Spring Batch is used for Bulk Operations.

>> Example: In Banking applications, sending bank statements to millions of customers at a time.

>> Suppose HDFC Bank takes 1 minute to send a statement to 1 customer. For 1 lakh customers, it would take 1,00,000 minutes (nearly 69 days).

>> If you receive your April bank statement in June, will you continue using that bank? Obviously no.

>> To process huge amounts of data quickly and efficiently, Spring Batch came into the picture.

✔ Spring Scheduler

>> Spring Scheduler is used to schedule tasks at a specific time automatically.

>> Example: If we set an alarm every day at 9 AM, it rings automatically at the scheduled time.

>> Similarly, in companies, salaries are scheduled to be credited automatically on the 1st of every month.

>> In short, Spring Scheduler is used for time-based automated tasks.

✔ Microservices

✔ Microservices Architecture vs Monolithic  

📌 Monolithic(All Features In One Single APP) Architecture:

>> Suppose MakeMyTrip has Flight Booking, Hotel Booking, Payment, and Notification in one single application.

>> If the Flight Booking module fails, the entire application may be affected.

📌 Microservices Architecture:

>> In Microservices, MakeMyTrip is divided into separate services:

Flight Service | Hotel Service | Payment Service | Notification Service

>> If Flight Service goes down, users can still access Hotel Booking and other available services.

>> Advantages:
✔ Loose Coupling  
✔ Easy Deployment  
✔ Easy Modification & Maintenance  
✔ Independent Services  
✔ If one service fails, other services still work
