>> DIAGRAM

>> In Java, multiple inheritance is not supported.

>> Here, UserService directly creates the object using `new`, so classes become tightly coupled.

📌 Drawback 1: Tight Coupling (Manual Object Creation)

UserService.java

class UserService {

    UserRepository repo = new UserRepository(); // Tight Coupling

    public void saveUser() {
        repo.save();
    }
}

UserRepository.java

class UserRepository {

    public void save() {
        System.out.println("User Saved");
    }
}

>> Here, UserService directly creates the object using `new`, so classes become tightly coupled.

>> If repository logic changes or we need another implementation, code changes are required everywhere.

>> Spring Core solves this problem using IOC (Inversion of Control) and DI (Dependency Injection).


📌 Drawback 2: Multiple Inheritance Not Supported

class A {
    void m1() {
        System.out.println("A Method");
    }
}

class B {
    void m2() {
        System.out.println("B Method");
    }
}

// Not Allowed in Java
class C extends A, B {

}

>> In Java, multiple inheritance is not supported.

>> If a class needs functionalities from multiple classes, managing dependencies becomes difficult.

>> Spring DI helps inject required dependencies without inheritance problems.


📌 Drawback 3: Boilerplate Code / Dependency Management

class EmployeeService {

    EmployeeRepository repo = new EmployeeRepository();

    EmailService email = new EmailService();

    SMSService sms = new SMSService();

}

>> In large-scale applications, creating objects manually for every dependency becomes difficult to manage and maintain.

>> Spring Core automatically manages object creation and dependency injection.


📌 Solution: Spring Core (IOC + DI)

@Service
class UserService {

    @Autowired
    UserRepository repo;

    public void saveUser() {
        repo.save();
    }
}

@Repository
class UserRepository {

    public void save() {
        System.out.println("User Saved");
    }
}

>> Spring automatically creates objects and injects dependencies.

>> No manual object creation (`new`) is required.

>> Applications become loosely coupled, maintainable, scalable, and easier to test.
